**Логика очистки демо-данных:**
```typescript
async function clearDemoData() {
  const demoTasks = await db.tasks.filter(t => t.isDemo === true).toArray()
  const demoEvents = await db.calendarEvents.filter(e => e.isDemo === true).toArray()
  const demoTransactions = await db.transactions.filter(t => t.isDemo === true).toArray()
  
  for (const task of demoTasks) await db.tasks.delete(task.id)
  for (const event of demoEvents) await db.calendarEvents.delete(event.id)
  for (const tx of demoTransactions) await db.transactions.delete(tx.id)
  
  // Обновляем стейт
  useDashboardStore.setState({ dataMode: 'real' })
}
```

## ⚠️ Возможные побочные эффекты

1. **Существующие данные без `isDemo`:**
   - Все старые записи будут считаться "реальными"
   - Решение: добавить миграцию, установить `isDemo: false` по умолчанию

2. **Синхронизация с облаком:**
   - Демо-данные не должны синхронизироваться
   - Нужно добавить фильтр в sync-engine: `if (isDemo) return`

3. **Индексация `isDemo`:**
   - Сейчас поле не проиндексировано в Dexie.js
   - Для больших БД (>1000 записей) фильтрация может быть медленной
   - Рекомендуется добавить индекс: `tasks: 'id,isDemo'`

4. **Многопользовательский режим:**
   - Демо-данные используют `user_id: 'demo-user'`
   - Для multi-user нужно адаптировать логику
